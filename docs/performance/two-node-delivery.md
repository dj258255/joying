# 서버가 두 대가 되면 순서가 유지되는가

## 왜 다시 쟀나

순서를 지키려고 만든 장치는 전부 한 프로세스 안에 있다. 들어오는 채널을 연결 단위로
묶은 것도, 방 단위로 한 줄로 세운 것도, 나가는 채널의 발행 순서를 켠 것도 그렇다.

서버가 둘이면 그 사이에 Redis 를 건너는 구간이 하나 더 생긴다. 그 구간은 어느 장치도
덮지 않는다.

앞선 실험은 전부 한 대에서 했고, 기록에도 "두 노드에서 재지 않았다"고 적어 두었다.

## 잰 조건

| 항목 | 값 |
|---|---|
| 서버 | 같은 저장소를 보는 앱 두 대. 포트만 다르다 |
| 보내는 사람 | 8명 전부 1번 노드(8080)에 붙는다 |
| 받는 사람 | 1명이 2번 노드(8081)에 붙는다 |
| 부하 | 각 25건, 총 200건을 연결 직후 몰아서 전송 |
| 실행 | 3회 |

보내는 쪽과 받는 쪽을 다른 노드에 붙이는 것이 핵심이다. **한 대에 섞어 붙이면 일부는
서버 안에서 끝나 무엇을 재는지 갈린다.**

실행: `k6 run load/k6/two-node-delivery.js`

## 건넜다는 것을 먼저 확인했다

수치를 보기 전에 메시지가 실제로 노드를 건넜는지부터 봤다. 붙는 곳만 바꿔 놓고 사실은
한 대에서 끝나고 있으면 수치가 아무 뜻이 없다.

| | 1번 노드 | 2번 노드 |
|---|---|---|
| 저장·발행한 건수 | 1,200 | **0** |
| 웹소켓 연결 | 24 | 3 |

2번 노드는 한 건도 저장하지 않았다. 받기만 했다. 연결 수도 보내는 사람 8명 × 3회와
받는 사람 1명 × 3회로 갈렸다.

## 결과

| 받는 사람이 붙은 곳 | 뒤집힘 (200건 중) | 왕복 중앙값 | 왕복 p95 |
|---|---|---|---|
| 같은 노드 (서버 안에서 끝남) | 0 · 0 · 0 | 1.54s · 1.48s · 1.51s | 2.80s · 2.72s · 2.80s |
| **다른 노드 (Redis 를 건넘)** | **0 · 0 · 0** | 1.83s · 1.56s · 1.38s | 3.14s · 2.87s · 2.80s |

사라진 메시지는 양쪽 모두 0건이다.

**순서는 노드를 넘어서도 유지된다.** 지연도 눈에 띄게 달라지지 않았다. 세 번을 재면
값이 겹치는 구간에 있다.

## 왜 유지되는가

Redis 발행이 방 단위 실행기 한 줄에서 나가기 때문이다. 그 줄이 순서대로 발행하고,
Redis 는 한 구독 연결에 보낸 순서대로 전달한다. 받는 노드는 그것을 스레드 하나로 받아
방 단위 실행기에 넘긴다.

**한 대에서 순서를 지키려고 만든 것이 그대로 두 대에서도 작동한다.** 새로 넣은 것은
없다.

## 보내는 사람을 갈라 붙이면 드물게 뒤집힌다

여기까지는 보내는 사람을 전부 1번 노드에 붙였다. 그러면 발행이 한 줄에서 나가므로
순서가 지켜진다.

갈라 붙이면 다르다. 번호는 여전히 Redis 증가 연산 하나가 정하지만, **두 노드가 각자
발행한다.** 1번에서 41번을 발행하는 것과 2번에서 42번을 발행하는 것 사이에는 아무
순서가 없다.

발신자 8명을 홀짝으로 나눠 두 노드에 붙이고 18회 돌렸다.

| | 값 |
|---|---|
| 뒤집힘이 난 실행 | 18회 중 **1회** |
| 그때의 뒤집힘 | 200건 중 **4회** |
| 나머지 17회 | 0 |
| 사라진 메시지 | 전 실행 0건 |

**드물지만 실재한다.** 한 번만 재고 0을 봤으면 없다고 적었을 것이다.

이것이 이 설계의 경계다. 서버 안에서는 줄을 세워 순서를 만들 수 있지만, 서버 사이에는
줄이 없다. 번호가 순서를 정하는 근거로 남아 있고 화면이 그것으로 정렬하므로 최종
표시는 맞다. 실시간으로 이어 붙이는 화면에서만 드물게 어긋났다가 제자리를 찾는다.

한 방의 사람들을 같은 노드로 모으면 사라지는 문제지만, 그러려면 방을 기준으로 붙는
곳을 정해야 하고 그 장치는 지금 없다.

## 이것으로 확인되지 않은 것

- **노드가 셋 이상일 때를 재지 않았다.**
- **한 노드가 죽었을 때를 재지 않았다.** 붙어 있던 사람들이 다른 노드로 옮겨 붙는
  동안 무엇이 사라지는지 모른다.
- **같은 기계에서 두 프로세스를 띄웠다.** 실제로 떨어진 두 기계 사이의 지연은 더 크다.
