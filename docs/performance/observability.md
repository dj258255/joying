# 지표가 멀쩡해 보이는데 사용자는 59초를 기다리고 있었다

## 왜 만들었나

부하로 재서 알아낸 것들은 한 번 하고 끝난다. 같은 일은 배포한 뒤에도 일어나는데,
그때는 k6 를 돌릴 수 없다. 실험에서 본 것을 운영에서도 볼 수 있어야 한다.

이 프로젝트에는 관측이 아예 없었다. actuator 도, 지표 수집도, 대시보드도 없었다.

![Grafana 채팅 전달 대시보드](screenshots/grafana-chat-slo.jpg)

## 무엇을 지켜볼지 어떻게 골랐나

기준은 "무너질 때 먼저 움직이는가" 로 잡았다.

| 지표 | 왜 |
|---|---|
| 줄에서 기다린 시간 | 사용자가 겪는 것의 대부분이 여기서 나온다 |
| 가장 많이 밀린 줄의 길이 | 저장소가 느려질 때 가장 먼저 움직인다 |
| 같은 전송이 다시 들어온 비율 | 오르면 발행이 실패하고 있다는 뜻인데 오류 로그에는 안 남는다 |
| 번호를 못 받아 저장을 막은 건수 | 0이 아니면 메시지가 저장되지 않고 있다 |

줄 길이는 평균이 아니라 **가장 나쁜 줄**을 본다. 방마다 줄이 따로 있어서 평균을 내면
한 방에 몰린 것이 묻힌다.

## 만들고 나서 바로 틀린 것을 찾았다

처음에는 저장 시각부터 화면에 나갈 때까지를 쟀다. 그것으로 부하를 넣어 보니 이렇게 나왔다.

| | 값 |
|---|---|
| 대시보드가 보여 준 전달 p95 | **0.4초** |
| 같은 시각 k6 가 잰 왕복 중앙값 | **59초** |
| 같은 시각 줄 길이 | **199** |

**지표는 멀쩡한데 사용자는 59초를 기다리고 있었다.**

저장 시각은 줄에서 빠져나온 뒤에 찍힌다. 기다린 시간이 통째로 지표 밖에 있었다.
줄에 넣기 직전의 시각을 따로 찍어 그때부터 처리가 시작될 때까지를 재고, 대시보드도
대기와 전달을 더한 값으로 바꿨다.

바꾸고 나니 지연을 주입했을 때 p95 가 30초로 붉게 물든다. 위 그림에서 줄이 198까지
솟은 자리와 정확히 겹친다.

## 걸렸던 것

**게이지 이름에 `total` 을 쓰면 안 된다.** `chat.executor.queue.total` 로 두었더니
`chat_executor_queue` 로 내보내졌다. Prometheus 에서 그 접미사는 계속 늘어나는 값에
붙이는 관례라 Micrometer 가 게이지에서는 떼어 버린다. 대시보드 질의가 이름을 못 찾아
`No data` 가 떴다. `depth` 로 바꿨다.

**백분위만으로는 여러 대를 합칠 수 없다.** 서버마다 계산한 백분위는 더할 수 없다.
히스토그램으로 내보내도록 설정을 켰다. 이것을 안 켜면 `_bucket` 계열이 없어
`histogram_quantile` 이 아무것도 돌려주지 않는다. 실제로 대기 시간 지표에서 겪었다.

**긁는 주기 기본값 15초로는 안 보인다.** 저장소가 느려질 때 줄이 쌓였다가 빠지는 것은
수십 초 안에 일어난다. 5초로 줄였다.

## 무엇을 열었나

`/actuator/health` 와 `/actuator/prometheus` 둘만 연다. 기본으로 열리는 것 중에는
설정값과 빈 목록처럼 밖에 보여 줄 이유가 없는 것이 섞여 있다.

인증을 걸지 않은 이유는 긁어 가는 쪽이 사람이 아니어서다. 대신 밖에서 닿지 않게 막는
것은 네트워크에서 한다. 지금은 로컬 도커 안에서만 부르고, 배포할 때 이 경로를 외부에
열지 않는다.

## 어떻게 띄우나

```
docker compose -f infra/observability/docker-compose.yml up -d
```

Grafana 는 `http://localhost:3001`, Prometheus 는 `http://localhost:9091` 이다.
3000과 9090은 다른 것이 쓰고 있을 수 있어 비켜 두었다.

## 아직 하지 않은 것

- **경보가 없다.** 대시보드만 있다. 줄이 얼마나 길어지면 사람을 불러야 하는지 정하려면
  정상 상태의 분포를 먼저 알아야 하는데, 실 트래픽이 없어 정하지 못했다.
- **결제 쪽 지표가 없다.** 결제 생성 경합을 부하로 재서 고쳤지만 그것을 운영에서 볼
  지표는 만들지 않았다.
- **한 대에서만 봤다.** 여러 대를 띄우면 지표에 서버 이름이 붙어야 하는데 확인하지
  않았다.
- **로그와 이어 두지 않았다.** 지표에서 이상을 보고 로그로 넘어가는 길이 없다.
